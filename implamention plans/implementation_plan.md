# Donation Receipts Editor — Refined Implementation Plan

Based on the `/grill-me` interview session. All design decisions are resolved below.

---

## Confirmed Design Decisions

| # | Decision | Answer |
|---|---|---|
| 1 | Scope | Both email body AND PDF content |
| 2 | Template granularity | Per-type (one-time, monthly) AND per-tier — maximum granularity |
| 3 | Variable insertion method | Dynamic placeholders: `{donorName}`, `{amount}`, `{tierName}`, `{date}` |
| 4 | PDF control level | Text-only sections: thank-you message, footer note, signature name |
| 5 | Email preview | Live read-only preview with sample data substituted in |
| 6 | Email editable fields | **Subject line only** — body is auto-generated by the system |
| 7 | PDF editable sections | Thank you message, footer note, signature name |
| 8 | Transaction subjects | Admin-defined free-form labels/tags added to individual transactions |
| 9 | Subject visibility | Subject appears in the email subject line only (not on the PDF) |
| 10 | Re-send behavior | Internal-only for now — no retroactive re-sends |
| 11 | UI structure | Dedicated "Receipt Settings" sidebar page + CMSTransactions inline subject editing |

## Proposed Changes

### Layer 0 — Database Schema

#### [MODIFY] `server/prisma/schema.prisma`

**1. `ReceiptSettings` model** — Stores configurable email subject templates and PDF text. Keyed by donation type with a fallback global record (id: 1).

```prisma
model ReceiptSettings {
  id                 Int      @id @default(autoincrement())
  donationType       String   @unique @default("GLOBAL")
  // "GLOBAL" | "ONE_TIME" | "RECURRING" | "TIER_{tierId}"

  emailSubjectTemplate String  @default("Thank you for your donation — Official OMP Receipt 🎉")
  // Supports: {donorName}, {amount}, {tierName}, {date}, {transactionSubject}

  pdfThankYouMessage String  @default("We appreciate your generous support.")
  pdfFooterNote      String  @default("This PDF is your official donation receipt. Please retain for your records.")
  pdfSignatureName   String  @default("The OpenmindProjects Team")

  updatedAt          DateTime @updatedAt @map("updated_at")

  @@map("receipt_settings")
}
```

**2. `Transaction` model** — Add an optional `subject` field for admin-defined labels.

```prisma
model Transaction {
  // ...existing fields...
  subject    String?  // Admin-defined label, injected into email subject line
  adminNote  String?  // Internal-only note, never sent to donor
  // ...
}
```

> [!IMPORTANT]
> After schema changes, run: `npx prisma db push` then `node server/prisma/seed.js` to create the default `GLOBAL` ReceiptSettings row.

### Layer 1 — Backend API

#### [NEW] `server/src/controllers/admin/receiptSettingsController.js`
- `getReceiptSettings()` — returns all settings rows (GLOBAL + type-specific + tier-specific).
- `updateReceiptSettings(donationType, payload)` — Zod-validates and upserts the row by `donationType`.
- `resolveReceiptSettings(donationType, tierId?)` — internal helper used by email triggers. Resolves the most specific settings row (tier > type > global) and substitutes dynamic variables.

**Zod schema:**
```js
const ReceiptSettingsSchema = z.object({
  emailSubjectTemplate: z.string().min(3).max(200),
  pdfThankYouMessage:   z.string().max(500),
  pdfFooterNote:        z.string().max(300),
  pdfSignatureName:     z.string().max(100),
});
```

#### [NEW] `server/src/routes/admin/receiptSettings.js`
```
GET  /api/admin/receipt-settings         → list all
GET  /api/admin/receipt-settings/:type   → get by donationType
PUT  /api/admin/receipt-settings/:type   → upsert by donationType
```

#### [MODIFY] `server/src/routes/admin/transactions.js`
- Add `PATCH /api/admin/transactions/:id` — update `subject` and `adminNote` for a transaction.

#### [MODIFY] `server/src/controllers/admin/adminTransactionController.js`
- Add `updateTransactionMeta(req, res, next)` to handle `PATCH /:id`.
- Validate that only `subject` and `adminNote` can be updated (never amount, userId, status).

#### [MODIFY] `server/src/routes/admin/index.js`
- Register the new `receiptSettings` router under `/receipt-settings`.

### Layer 3 — Email & PDF Integration

#### [MODIFY] `server/src/middleware/prismaEmailTrigger.js`
- Before calling `sendEmail`, call `resolveSettings(...)` to get the correct settings row.
- Call `interpolate(settings.emailSubjectTemplate, variables)` to produce the final subject.
- Pass `pdfThankYouMessage`, `pdfFooterNote`, `pdfSignatureName` to the `receiptData` payload.
- Inject `transaction.subject` into `variables.transactionSubject`.

#### [MODIFY] `server/src/controllers/public/webhooksController.js`
- Apply the same `resolveSettings` + `interpolate` pattern for Stripe-triggered receipts.

#### [MODIFY] `server/src/services/receiptPdfDraw.js`
- Accept `pdfThankYouMessage`, `pdfFooterNote`, `pdfSignatureName` from `receiptData`.
- Replace the current hardcoded strings with the dynamic values.

### Layer 4 — Admin UI

#### [NEW] `client/src/components/admin/CMSReceiptSettings.jsx`
A settings editor with tabbed sections — one tab per donation type:
- **Global (Fallback)**
- **One-Time Donations**
- **Monthly Subscriptions**
- **Per-Tier** — rendered dynamically from the loaded tiers list.

**Fields per tab:**
- Email Subject Template (with variable chips shown in a helper row below the input)
- PDF Thank You Message
- PDF Footer Note  
- PDF Signature Name

**Live Preview Panel** (right-side column):
- Renders the email subject in real time, replacing variables with sample values.
- Sample data: `{donorName}` → "Alex Johnson", `{amount}` → "$25.00", `{tierName}` → "Silver", `{date}` → today's date.

#### [NEW] `client/src/components/admin/CMSReceiptSettings.css`
- Tabbed layout styles, preview panel styles, variable chip styles.
